# المعمارية التقنية (شرح مبسّط)

## الصورة العامة

```
┌───────────────────────────┐     ┌──────────────────────────┐
│  تطبيق Flutter            │     │ إضافة المتصفح (Chrome)   │
│  جوال / ويب / حاسب        │     │ تعمل داخل نور ومدرستي     │
└────────────┬──────────────┘     └────────────┬─────────────┘
             │  HTTPS                            │
             ▼                                   ▼
        ┌────────────────────────────────────────────┐
        │  Supabase                                    │
        │  • Auth: تسجيل الدخول                       │
        │  • PostgreSQL: البيانات + سياسات RLS         │
        │  • Storage: الملفات والشواهد                │
        │  • Edge Functions: المنطق الخاص والدفع       │
        └────────────────────────────────────────────┘
```

## لماذا هذه التقنيات؟

- **Flutter**: نكتب الكود مرة واحدة فيعمل على ستة أنظمة. دعمه للعربية واتجاه اليمين لليسار ممتاز، وأداؤه قريب من التطبيقات الأصلية.
- **Supabase**: قاعدة بيانات PostgreSQL حقيقية، أي بيانات مترابطة (مدرسة ← فصول ← طلاب ← درجات)، مع تسجيل دخول جاهز. ميزة **RLS** (أمان على مستوى الصف) تمنع أي معلم من رؤية بيانات مدرسة أخرى حتى لو حدث خطأ في التطبيق. وهي مفتوحة المصدر، فيمكن لاحقاً استضافتها على خادم داخل السعودية لتوافق نظام حماية البيانات.
- **إضافة المتصفح**: نور ومدرستي لا يوفران واجهة برمجية عامة. الإضافة تقرأ الصفحات التي يفتحها المعلم بنفسه وبموافقته، كما يفعل تطبيق تحضيري، ثم ترسل البيانات إلى حسابه في مرقاة.

## تنظيم كود التطبيق (`app/lib`)

```
main.dart                 نقطة البداية: تهيئة الخادم وتشغيل التطبيق
app.dart                  إعداد اللغة العربية والثيم والتنقل
core/
  config/env.dart         إعدادات الخادم (تُمرَّر وقت التشغيل لا في الكود)
  theme/                  الألوان والخطوط والثيم الفاتح والداكن
  router/app_router.dart  خريطة الشاشات وحماية الصفحات
  auth/                   حالة تسجيل الدخول (حقيقي أو تجريبي)
features/                 كل ميزة في مجلد مستقل
  auth/                   شاشة الدخول
  home/                   الهيكل الرئيسي والقائمة
  dashboard/              لوحة المعلم
```

**قاعدة مهمة**: كل ميزة جديدة (الحضور، الدرجات، ...) تُضاف في مجلد خاص تحت `features/`. بهذا يبقى المشروع منظماً مهما كبر.

## الأدوار والصلاحيات

| الدور | يرى |
|-------|-----|
| `owner` مالك المنصة | كل شيء (لوحة العملاء والاشتراكات) |
| `principal` مدير / `deputy` وكيل | كل بيانات مدرسته |
| `teacher` معلم | فصوله وطلابه فقط |
| `parent` ولي أمر | أبناؤه فقط |
| `student` طالب | بياناته فقط |

المستخدم الواحد قد يكون معلماً في مدرسة ووكيلاً في أخرى، لذلك الدور مرتبط بالعضوية في المدرسة (`school_members`) وليس بالمستخدم.
